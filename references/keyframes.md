# 关节动作 GIF

用户要的手势会改变手臂、手或其它身体部位时，走这套流程。

两个脚本的分工要分清：

| 脚本 | 能力 |
| --- | --- |
| `export_pack.py` | 对**单一姿势**做位移与形变 |
| `export_keyframes.py` | 按顺序播放**多张不同的**生成姿势 |

两者默认都出透明 512px GIF，但**只有后者能真正表现肢体改变姿势**。

## 生成并检查连续姿势

- **先规划一个短手势，3–8 个关键姿势**。例如：手放低 → 小臂抬到一半 → 拇指到胸前 → 拇指贴到脸颊旁。返回序列可以把格子倒序复用。
- **生成的图里不要带文字**。
- **同一角色的连续姿势放在同一行**，用等格透明图集。提示词里固定这些：头部中心、机位、光照、缩放比例、服装、躯干基线。只改要动的那个肢体或表情。每一帧都要包含完整的头发、帽子、手肘、手指，格间距留够。
- 写实人物用参考图锁定身份；插画角色保持动漫风格。**每一格都要看**：肢体被切、头顶被裁的要重生成；背景被烤进图里时，明确要求图像工具恢复真透明。**"请给透明背景"这句话本身不构成 alpha 全零的证据，要自己验。**
- **所有格子放在同一坐标系里**。不要每格单独裁切适配——手一动包围盒就变，头会跟着跳或缩放。导出脚本会取所有姿势包围盒的并集，然后对全部帧套用同一套适配。
- **看完整一轮**，查身份漂移和手部结构。帧与帧不同，不等于手势连贯。这是关键姿势动画，**不是光流插值，也不保证视频级平滑**。大批量动作套包开工前，先做一小份验收通过的小样。

## 清单与导出

关键帧用单独的清单，字段还是熟悉的 `title`、`count`、`groups`。路径相对清单文件，格子坐标从 0 开始。**帧的顺序就是时间顺序，允许重复引用同一格。**

```json
{
  "title": "点赞小样",
  "count": 1,
  "groups": [{
    "name": "点赞",
    "atlas": "thumbs-up.png",
    "grid": [4, 1],
    "entries": [{
      "name": "人物-稳了",
      "text": "稳了",
      "frames": [
        {"cell": [0, 0], "duration": 320},
        {"cell": [1, 0], "duration": 120},
        {"cell": [2, 0], "duration": 120},
        {"cell": [3, 0], "duration": 320},
        {"cell": [2, 0], "duration": 120},
        {"cell": [1, 0], "duration": 120}
      ]
    }]
  }]
}
```

```sh
python3 scripts/export_keyframes.py actions.json build --font /path/to/font.ttf --preview
```

字段规则：

- `duration` 单位毫秒，默认 120，必须是 20 的正整数倍。上面这个例子一轮 1.12 秒。
- 条目可选 `ink` 改台词颜色。
- `name` 只决定文件名，**不影响画面上的台词**。
- 单帧可用 `crop: [left, top, right, bottom]` 覆盖裁切，但裁切后必须保持原格子尺寸（允许 1 像素误差）且对齐一致。
- 源图尺寸或取景不一致时，换别的合成器，别硬凑。
- 顶层可选 `credits`，会作为来源/制作说明写进 ZIP。

合成参数：源分辨率 LANCZOS 采样、所有帧共用一套裁切与缩放、512 × 512 输出、原尺寸台词、共用 GIF 调色板。它**不套用**单姿势那套挤压和动效预设。产出分类 GIF、离线画廊和校验过的 ZIP；加 `--preview` 会额外生成无标题的 MP4，按解码后 GIF 的真实时序拼装。预览每 16 张分页，每页播放该页最长循环的三轮。

验证覆盖：数量精确、文件互不相同、帧间确有变化、透明度、安全边距、循环时长、ZIP 内容。另外要**肉眼看一下实际播放**，包括最后一帧回到第一帧的那一下。不要声称单姿势导出脚本有 `frames` 参数——它没有；关键帧清单请用这个独立脚本。
